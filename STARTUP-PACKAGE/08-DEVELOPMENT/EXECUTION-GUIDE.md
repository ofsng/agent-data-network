# Development execution and release playbook
## 0 — before coding
Read README, decisions, PRD, Anchor spec, API, schema, task specs and tests. Verify actual event rules. Inspect existing repository without overwriting work; use separate branch, keep archive read-only. Install official skill and MCP after inspecting source and permissions:
```sh
npx skills add https://github.com/solana-foundation/solana-dev-skill
claude mcp add --transport http solana-mcp https://mcp.solana.com/mcp
```
Confirm `/mcp`, record skill revision and installed CLI versions. Do not trust generated snippets without actual compile/test. Use existing toolchain if compatible; no arbitrary nightly upgrades. H02 tests local validator and real funding, timebox x402 45 min. Record cluster genesis/network, program ID, mint, public wallets. No mainnet. Do not buy services or fund real SOL without approval.

## 1 — workspace and configuration
Anchor workspace, program ID generated by build, Rust/Anchor/TS versions pinned in lockfiles. App in Node runtime; SQLite persistent local path. `.env.example` names only: SOLANA_RPC_URL, SOLANA_CLUSTER, PROGRAM_ID, PAYMENT_MINT, TREASURY_PUBKEY, DATABASE_PATH, DELIVERY_DOMAIN, DEMO_BUYER_KEYPAIR_PATH, DEMO_PROVIDER_A_KEYPAIR_PATH, DEMO_PROVIDER_B_KEYPAIR_PATH, DEPLOYER_KEYPAIR_PATH. Key paths only server-side local CLI; public vars must never include secrets. Ignore `.env*` except example, keys, wallet files and private DB. Validate Devnet and local-only at startup. Tests use disposable local keys/mint. Document actual commands as implemented, not guessed versions. Use Git PR or small commits, format/lint/typecheck, cargo/anchor tests and app tests.

## 2 — build
H03: compile config/asset with explicit authority checks, test then IDL; H04: apply SQL migration in transaction, seed immutable bytes, generate canonical IDs/hashes, precreate ATAs. H05: implement CPI payment and receipt, build two-instruction tx, simulate and measure. H06: negative local tests, inspect balances and state after failed tx. H07: read APIs and wallet-bound delivery; no private endpoint before finalized verification. H08: deterministic agent; log actual signatures. H09/H10: escrow funding, submit, acceptance and refund; test deadline boundaries and repeated payout. H11: synthetic bounty validation, receipt and activate. H12: minimal read-only UI. Keep H13/H14 protected time. Details in TASK-SPECS and TEST-MATRIX.

## 3 — deployment and rollback
Run pinned clean build, local tests and dependency/secret scan. Check program authority/funding, cluster, exact legacy mint. Deploy to Devnet only; record actual program ID and IDL hash, initialize immutable config from authorized deployer, fund test ATAs and register assets. Execute demo purchase, bounty accept and separate expiry refund; verify finalized accounts, exact deltas, size/CU, fee/rent. Save evidence with real explorer URLs and timestamp. Start protected app, smoke search/receipts/nonce-delivery/gap. Do not expose signing endpoints. If deploy fails, keep local demo clearly labeled; no fake explorer links. If app regression, revert app commit with compatible schema; do not reset chain or delete receipts. If program issue, stop actions, preserve accounts/tx, only redeploy/upgrade after documenting new ID/authority and re-running tests. Old evidence remains labeled by program ID. No real production migration.

## 4 — completion checklist
- [ ] G0 rules confirmed, AI disclosure as required
- [ ] Local Anchor tests and API auth tests pass; no secret files
- [ ] Actual Devnet two-provider tx, two receipt PDAs, both exact deliveries
- [ ] Actual funded bounty, requester accept, provider/treasury split, bounty receipt and separate expired refund
- [ ] Atomic failure, replay, unauthorized recipients, invalid submission and deadline tests pass
- [ ] Measured serialized size, compute, SOL fee and storage deposit
- [ ] README with reproducible commands and actual program/mint/explorer links
- [ ] UI/CLI evidence, synthetic label, limitations and submission requirements verified
All unchecked until actual execution. No claim of completed implementation.
