# API contract | /api/v1 (spec, not implemented)
JSON camelCase; pubkeys base58, hashes lowercase 64 hex, IDs 32 hex (16 bytes), integer amounts decimal strings (u64); dates Unix seconds integer. All mutation/signing done by local CLI via generated Anchor IDL; API NEVER accepts private keys or signs arbitrary tx. Local/protected app only. 64 KiB body limit, search query max 256 chars, limit 1–20. Errors `{code,message,retryable}`. 400 invalid; 401 bad wallet proof; 403 wrong buyer; 404 missing; 409 stale/used nonce; 422 hash/terms mismatch; 429 rate; 503 chain unavailable; 202 pending finality.

CLI commands (suggested interface): `seed`, `search`, `quote`, `purchase`, `verify`, `deliver`, `gap`, `submit`, `accept`, `refund`, `activate`, `demo`. Read and decode IDL accounts using same PDA seeds as program. Local deterministic validator returns bounded review report per DATA-TRUST-SPEC before requester signs. Requirement v2 public metadata excludes expected answer. Legacy bounty hashes remain unchanged. UI triggers only guarded local demo actions or reads API; never expose server signer. No actual REST mutation of chain without signature. No webhook required; RPC reconciliation by receipt PDA. Optional x402 transport explicitly distinct from direct Anchor.

V1.4 trust object and status definitions: DATA-TRUST-SPEC. Missing/invalid trust or snapshot fails quote closed (422 validation/hash or 503 unavailable). Existing paid entitlement remains accessible even when listing withdrawn; trust metadata never overrides valid historical receipt. On delivery corruption return retryable 503 or 422; repair exact bytes via protected backup and require fresh nonce, no new charge. Optional local stdio tool contracts: AGENT-INTEGRATION-SPEC; no raw signing endpoint. No real public access.
