# Data Trust Layer — canonical V1.4 off-chain contract
P0, minimal implementation in existing src/data and API; no reputation engine, oracle, embeddings or external network lookups. No Anchor ABI changes. Synthetic records only; never market as verified facts.
## Trust boundaries
Integrity = exact content/license bytes match on-chain hashes; schema validity = software checks required fields; accuracy = factual truth, always UNVERIFIED in demo. Provider source/rights declaration is self-attested off-chain metadata, NOT committed by the existing content hash and NOT ownership proof. Do not imply source authenticity. Metadata access is free; never expose paid body, license secrets or solution through search, logs, previews, error strings, health or MCP tool schemas. Demo fixtures are publicly reproducible in repo; no cryptographic secrecy claim. Runtime access control tests still required.
## Import and metadata
- Keep V1.3 CSV canonical body and LICENSE bytes unchanged; 12 original IDs/version/hash values preserved. UTF-8 NFC, CRLF→LF; 1–65536 bytes; tags/title bounded and plain text; original textual bodies pass TEXT_V1 schema if nonempty. Bounty uses exact two-key JSON object with string fields, no extras. Reject malformed UTF-8, oversized or empty bytes, missing declaration, invalid timestamps, unexpected JSON shape. No automatic semantic accuracy claims.
- `asset_trust` sidecar (schema.sql / migration): asset_pda FK; source_label max 128 chars (e.g. `Synthetic fixture / NorthLab`); observed_at Unix seconds, positive and <= current time + 60s; rights_declared=1; schema_id TEXT_V1 or BOUNTY_JSON_V2; validation_status VALID or INVALID, accuracy_status UNVERIFIED; synthetic=1. New imports require explicit declaration before publishing. Existing known fixture records backfill from synthetic manifest/actual provider mapping; unknown records quarantine, never auto-assert rights. Do not alter existing body/hash/asset versions. Review metadata is immutable in ordinary flows; corrections requiring new content use new asset/version. Freshness = age in seconds at response, not a truth score.
- `trust` in search/quote response: `{sourceLabel, observedAt, ageSeconds, rightsDeclared, schemaId, validationStatus, accuracyStatus:"UNVERIFIED", synthetic:true}`. Mark source as provider-declared. Quote only finalized active rows with valid trust and available snapshot. No automatic provider reputation. Optional exact duplicate warning only; no duplicate claims or auto-ban from hash alone.
## Delivery and recovery
1. Before returning quote, for each unit fetch finalized chain terms, verify private stored body/license exact SHA-256, schema, and confirm a recoverable protected backup snapshot includes exact bytes/hash. On mismatch/unavailable/invalid return 422 or 503, no quote or signing. For accepted bounty similarly check private solution before signing. Direct on-chain users can bypass API checks: do not claim program enforces them.
2. Use persistent SQLite WAL and SQLite backup API (or VACUUM INTO consistent snapshot, never copy live WAL db alone). Back up after successful import/trust validation before publishing/quoting, snapshot immutable asset bytes and trust; restrict directory mode 0700, files 0600, outside git/public tree. Write temp then atomic rename, verify backup hashes. Backup is local resilience, not disaster recovery or guarantee. In app, record verified backup availability per asset via manifest/read verification; no secrets in backup. Retain purchased versions even after deactivate. For existing assets create snapshot before new quote; do not overwrite originals on mismatch.
3. After finalized receipt, require existing wallet challenge rules and verify exact bytes before release. If primary unavailable/mismatch, fail closed, log sanitized error, restore exact missing/corrupted bytes from known-good protected backup with hash and identity check; restore in isolated staging/read transaction then atomically repair affected row only. Do not overwrite newer receipts/bounties/nonce records by replacing live database. Reconcile SQL from finalized chain. Fresh signed nonce for free retry; no new payment. If no copy matches, mark unavailable, stop listing/quoting, retain receipt and report unresolved delivery. No automatic purchase refund in V1.4.
4. Negative tests: wrong bytes before quote, restart with valid data, simulate deleted/corrupt primary after payment, restore exact bytes from backup; no additional token movements; no raw bytes in error or logs. Test revoked listing preserves prior delivery. Chain and DB are not a single atomic transaction; commercial gate stays closed.
## Bounty review
Use versioned public requirement and private deterministic expectation in fixtures/bounty.json. Public requirement states equipment, field, schema, accepted format, fictional issuer and nonexclusive demo license; does NOT include requiredValue/solution. Hash exact canonical sorted JSON. `review` local trusted validator checks exact submitted private body against expected synthetic fixture, required key/schema, source/date/rights, content/license hashes and submission PDA. It returns `{bountyPda,submissionPda,assetPda,requirementHash,contentHash,licenseHash,checks:{schema,field,fixtureMatch,provenance,integrity,license},passed,preview:{equipment,field,schemaId,sourceLabel,observedAt,byteLength}}`; no answer/body/value or snippets; no validator secret exposed. Preview is not truth proof. Bind to exact selected submission and current finalized state, re-run immediately before requester signing. No public review endpoint. Requester signs exact acceptance only if all checks true within deadline, budget and allowlist. Program cannot enforce off-chain checks; direct signer may bypass. Honest producer can still be refused; no arbitration in hackathon. Existing V1.3 bounties retain their original requirement hash and are labeled LEGACY, not silently migrated or claimed protected; use a fresh V1.4 bounty ID for new demo. Full bytes released only through finalized bounty receipt + wallet proof; after acceptance provider activates if license allows. Separate expired bounty refund remains required.

## V1.5 simplification
Keep source/schema/rights/accuracy labels, bounded review, exact-byte preflight and wallet-bound delivery. A verified immutable per-asset local snapshot (private, hash-checked, atomic write) is sufficient instead of whole-database backup infrastructure; if existing SQLite backup works, keep it. Recovery repairs only exact asset bytes. No production disaster recovery. All runtime modes use same data access tests; simulated success is not chain proof. Local fixture public availability remains disclosed.
