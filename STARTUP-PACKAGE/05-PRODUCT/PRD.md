# PRD | V1.3
Roles: provider signs asset registration/status changes; buyer signs purchase and owns entitlement; requester signs bounty creation/accept/refund; provider signs submission; operator configures deployment once, no escrow sweep. API verifies wallet control for private delivery. Demo operator uses isolated local keys; no public signer endpoint. On-chain rules authoritative.

| ID | Feature / user story | Required behavior & acceptance | Errors / dependencies |
|---|---|---|---|
| R01 | Provider publishes a unit | Validate bounded UTF-8 input; canonical bytes SHA-256, license bytes SHA-256; store private immutable body; register asset signed by provider; show active only after finalized chain match | Invalid size/schema, duplicate ID/version, failed RPC; H03/H04 |
| R02 | Agent searches | Free metadata only (title/tags/short synthetic teaser, version, license, price, provider); deterministic rank, active assets only; missing required tag => gap, no invented result | Empty results, stale chain; H04/H07 |
| R03 | Buyer quotes bundle | Choose two distinct providers, exact asset IDs/versions/prices/hash, buyer, expiry, nonce, max spend and SOL estimate. Quote no authorization to spend | Stale, duplicate, insufficient funds/budget; H05/H07 |
| R04 | Buyer purchases | Two purchase_unit instructions in one signed transaction; each transfers provider/platform share and creates receipt; any failure reverts both; report final signature and per-wallet deltas | Wrong signer/mint/ATA, expiry/replay/size; H05/H06 |
| R05 | Buyer verifies/delivers | Only wallet-bound verified finalized receipts unlock exact body & license bytes; SHA-256 match; retry same receipt free; no public raw body endpoint | Wrong buyer, forged receipt, hash mismatch, temporarily unavailable; H07/H08 |
| R06 | Requester funds gap | Explicit max bounty budget; hash canonical public-safe requirements; lock reward in unique PDA token vault; status OPEN | Balance/deadline/invalid mint; H09 |
| R07 | Provider submits | Register inactive new asset; sign submission bound to bounty and asset; requester can inspect bounded review preview in synthetic demo, then deterministically validate required fields; no release on upload | Not provider, expired, wrong asset/license; H09 |
| R08 | Requester accepts or refunds | Accept selected valid submission before deadline; split escrow, create bounty receipt, mark ACCEPTED; expiry refund full funded reward to requester, no fee; reject repeat/unauthorized calls | Race, wrong vault, wrong recipient; H10 |
| R09 | Agent completes research | Deterministic controller selects two paid units then reports source IDs, receipt addresses, hash match; missing field triggers one approved bounty; after acceptance may read via bounty receipt | Budget cap includes funded rewards; no free raw facts, no fake reasoning | 
| R10 | User sees chain evidence | Single dashboard with catalog, purchase, receipt, bounty tabs; pending/finalized/error states; Explorer links, test mint badge and real vs synthetic distinction | No green success on mock or pending; H12 |
| R11 | Provider withdraws listing | Provider toggles active only; immutable price/license/content/version. Past receipts stay valid; new purchases reject inactive asset | Unauthorized mutation; H03/H06 |
| R12 | Demo can be reproduced | README, pinned dependencies, local validator tests, Devnet program ID, tx links, no secrets, recorded fallback status | H13/H14 |

UX: responsive single page; top status (cluster/mint/program), search result cards with metadata, cart shows token and SOL separately, buyer signs exact transaction through local CLI, receipts verify, bounty state and vault balance; screen-reader labels, keyboard focus and high contrast. CLI is authoritative action interface; UI may read only. No browser keys or real uploads; local CSV/text import/seed plus optional UI text form if time. No PDFs, LLM, full auth product, vector DB, graph DB, production deploy, arbitrary public access, arbitration, cross-chain or custom currency sale.

Metrics: 2 distinct providers paid exactly, 2 finalized purchase receipts for one tx, 2 verified deliveries; 1 funded/accepted bounty + independent expired refund; 0 unauthorized releases/replays/partial payments; test runtime and serialized size recorded. Target not actual. All critical gates in TEST-MATRIX.
