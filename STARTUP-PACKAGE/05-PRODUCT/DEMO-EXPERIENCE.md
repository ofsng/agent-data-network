# Demo experience — mandatory product contract
## Goal
Within a single coherent browser session demonstrate why Solana matters: two independent providers paid atomically, independently inspectable paid entitlement, funded information gaps and repeat contributor revenue. Synthetic solar inverter X100. Default UI English, judge-ready, with a restrained dark ink/mint palette and readable typography. Use actual state, never prepaint success. No landing-page-only demo.
## Screen layout
Top: ADN / Discover · Purchase · Verify · Commission · Reuse; mode `LOCAL VALIDATOR — REAL TRANSACTIONS`, `DEVNET — TEST ASSETS`, or `SIMULATION — NO ON-CHAIN EXECUTION`; synthetic badge; reset/run controls. Left: agent task, budget (token + separate SOL), tool trace. Center: results/cart, trust details and step-by-step cards. Right: live balances/receipt/escrow evidence drawer. Bottom: readable run status, error/retry, optional MCP/x402 capability badges. Responsive, keyboard focus, no secrets or raw private prepay body. Local tx signature + decoded PDA/balance, Devnet Explorer only in Devnet mode. No sample number displayed as measured evidence.
## Guided state machine
READY → PUBLISHED → SEARCHED → QUOTED → PAYMENT_PENDING → PURCHASED → VERIFIED → GAP → BOUNTY_FUNDED → SUBMITTED → REVIEWED → ACCEPTED → DELIVERED → ACTIVATED → RESOLD → REFUND_DEMONSTRATED → COMPLETE. Failed step shows actionable error and retains prior evidence; no advance on failed validation. Manual advance and auto-run call the same real service; do not animate fake completion. Reset confirms new isolated run. Review panel shows pass/fail and metadata only; full solution after signed accept and wallet proof. Include rejected sample or expired refund as distinct scene, never take money from accepted bounty twice.

Exact values are fixture expectations, not pre-recorded actual results. For refund use a separate requester/budget or explicitly operator-authorized isolated negative-test run; original agent's 2.1 TEST cap must not silently expand. No extra bounty from same agent run. Show optional x402 / MCP as verified only after actual integration. If model credentials absent, deterministic agent drives same tools; label it. All economic steps have actual local-chain target. If toolchain unavailable, simulation mode must render entire flow with explicit simulation banner and technical gate not met.
## Demo acceptance
One command to launch after setup; no manual database edits or separate wallets in browser; two clean repeat runs with distinct IDs; no unhandled UI errors; pending state must resolve or clearly block; no data leaks or fake evidence. Capture screenshots and optional screen recording if supported. Evidence file includes run ID, mode, program ID when real, actual signatures, balances, receipt addresses, hash checks, acceptance/refund/resale, test results and known limitations.

Evidence schema (actual values only): `runId`, `mode`, `programId` (null for simulation), `mint`, `steps[]` with status and duration, `transactions[]` with actual signatures/slot/fee and decoded balance deltas (empty for simulation), `receipts[]`, `bounties[]`, `hashChecks[]`, `tests[]`, `technicalGate`, `uxGate`, `limitations[]`. A simulated run may include separate `simulatedEvents[]` with non-chain IDs; never populate actual transaction fields. UI uses this same evidence structure.
